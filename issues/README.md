# 跟进事项

需要**长期跟进**的事项——不是 bug 报告，而是「过段时间要回来看一眼」的事。

## 和 GitHub issue 的分工

| | 放这里 | 放 GitHub issue |
|---|---|---|
| 性质 | 个人跟进、无外部协作 | 需要讨论、有外部参与者 |
| 例子 | 「下周复测网络」「试试某工具」 | 「这个功能有 bug」 |
| 可见性 | 私有（仓库公开也不影响，因为没开） | 公开 |

**一个事项只放一处**，不要两边都写。

## 格式

每条带日期和复查条件，例如：

```markdown
## 复测 GitHub 可达性
- 建立：2026-10-11
- 原因：网络限制是动态的，当天就出现过从 0/5 到 5/5 的反转
- 复查条件：任何 git 操作失败时
- 方法：见 notes/env/github-access.md 第五节
```
